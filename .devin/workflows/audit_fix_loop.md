# Audit Fix Loop — фиксим по борду, не по вдохновению

Role: **FIXER** (эта сессия) + **AUDITOR** (вторая сессия, независимая).
Источник истины — актуальный датированный борд
`.devin/audit-YYYY-MM-DD.md` (компактный): находки `#N` с приоритетами;
полные `file:line` доказательства — в `.devin/archive/` (evidence-лог
борда). Каталог повторяющихся ран: `.devin/SIGNATURES.md` +
`AGENTS.md` §«Generated-code signatures».
**Борд закрыт для чтения — открыт для фиксов.** Не ищи новых багов
«заодно» — фиксишь пронумерованное.

## Invocation

> «прогони audit_fix_loop» / «фикси по борду» — сессия работает
> автономно до стоп-условия.

## Общие правила (наследуются, не дублируются)

`README.md` в этой папке — темп, формат отчёта, коммит-дисциплина.
`AGENTS.md` — закон и конвенции. `../WORKFLOW.md` — маршруты,
QUESTIONS-протокол, стоп-условия. Пространство `S###`
(`.devin/BOARD.md`) — чужое; этот цикл работает только `#N`.
Ниже — специфика этого цикла.

## Как работает двух-агентный цикл

- **FIXER (эта сессия):** берёт верхнюю неисправленную находку, фиксит,
  гоняет гейты, помечает в борде `[fixed → commit-hash]`, коммитит.
  Один раунд = одна находка (пакет родственных одним классом допустим —
  «все X одного механизма» — это одна находка по духу).
- **AUDITOR (вторая сессия):** по каждому `[fixed]` — re-check как в
  `cleanup_verify.md`: открыть строки, прогнать оригинальный поиск,
  проверить что фикс реален (не `pass`→`return None`), что тесты/гейты
  зелёные, что не сломан blast radius. Вердикт в борд: `[verified]`
  или `[rejected — причина]`. Rejected возвращается в очередь FIXER'а.

## Правила фикса (жёсткие)

- **Сначала verify строку**: борд писался по конкретному состоянию —
  `file:line` мог сдвинуться после предыдущих фиксов. Читай текущий
  код, не борд-слепок.
- **Тест до фикса где возможно** — падающий тест, доказывающий дефект,
  потом зелёный после фикса. Env-специфика (нет живой БД/сервиса):
  НЕ фейкуй прогон — пиши по статическому контракту + помечай
  `env-blocked` в коммите и борде с командой разблокировки.
- **Не создавай новых доменов/абстракций/endpoint'ов** без потребителя
  (conformance rule AGENTS.md). Фикс сужает, а не расширяет поверхность.
- **Race-фиксы — только реальные**: UNIQUE constraint, транзакция/
  атомарный `UPDATE ... WHERE`, distributed lock, `INSERT … ON
  CONFLICT`. «Ещё один if» — не фикс.
- **Tenant-фиксы — в запросе**, не в post-filter на вызывающей стороне
  (удалить post-filter, добавить предикат в запрос — см. SIGNATURES).
- **Doc-drift фиксится в ту сторону, которую подтверждает код** — код
  истина, не docs.
- Гейты до коммита — полный блок из `../WORKFLOW.md` Шаг 4. Красные
  гейты — чинить, не коммитить.
- Коммит: по конвенции репо, без AI-attribution. Борд-строку обновлять
  в том же коммите.

## Метка в борде

После фикса рядом с находкой:
`→ FIXED <hash> (что сделано в одну строку)` — или
`→ ATTEMPTED <hash>, env-blocked verify` если живой прогон невозможен.
AUDITOR потом ставит `→ VERIFIED` или `→ REJECTED: причина`.

## Стоп-условия

- Очередь исчерпана → STOP, отчёт.
- Фикс требует решения владельца (меняет public API / удаляет живой
  код / трогает платёжный или auth контур сверх указанного) →
  `.devin/QUESTIONS.md`, Q-формат, брать следующую находку.
- Борд противоречит коду и разобраться нельзя → QUESTIONS, не гадать.
