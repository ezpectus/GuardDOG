# Mentor — автономная работа + обучение систем-дизайну

Invoke: «прогони mentor» / «mentor по <домену>». Это `WORKFLOW.md` в
режиме парного программирования: та же очередь приоритетов, те же
гейты, но ИИ объясняет и спрашивает, а не молча лепит.

**Глобальные правила — `.devin/workflows/README.md`**: темп (один
item = один раунд = один коммит, потолок 1,000 строк), формат отчёта,
коммит-дисциплина. Закон — `AGENTS.md`; очередь/маршруты/гейты —
`../WORKFLOW.md`. Mentor добавляет к шаблону отчёта поле
`■ Lesson:` — урок раунда обязателен.

## Отличие от обычного цикла

| WORKFLOW (молча) | mentor |
|---|---|
| Берёт верхний пункт и делает | Перед каждым нетривиальным шагом — вопрос в `QUESTIONS.md` |
| Коммитит и идёт дальше | После каждой правки — `**Lesson**`: какой паттерн/антипаттерн, почему так масштабируется |
| Минимум разговора | Человек отвечает → ИИ корректирует план, человек учится |

## Цикл

### 0. Orient

Как в WORKFLOW Шаг 0 (AGENTS.md → board → git → defects) + прочитать
`QUESTIONS.md`: есть ли OPEN-вопросы без ответа? Если да — ждать
ответа, другую работу по этим items не начинать.

### 1. Pick

Та же приоритетная очередь. Для выбранного item:

1. **Analyze out loud** — короткий блок пользователю: что за код, где
   антипаттерн (назвать: god-service / dual-write / silent-fail /
   copy-paste-detector / process-local-state / feature-envy /
   shotgun-surgery / placeholder theatre / interface width…), какой
   принцип нарушен (SOLID буква, KISS, DRY, YAGNI, fail-fast…), что
   будет при 2 репликах / 10x нагрузке.
2. **Если нетривиально** (меняет контракт, ≥2 вариантов, удаление
   кода, новая абстракция) → entry в `QUESTIONS.md` по формату файла,
   сказать «прочти QUESTIONS.md Q-NNN», **ждать ответа**.
3. Тривиальное (lint, typo, docstring-fix по согласованным правилам)
   → делать сразу, но Lesson всё равно писать в отчёт раунда.

### 2. Do

Минимальный дифф по конвенциям AGENTS.md + architecture-conformance
check из WORKFLOW Шаг 3. Паттерны предпочтительны там, где они уже
есть в коде — не импортировать паттерн ради паттерна; KISS бьёт
«правильность».

### 3. Verify

Те же gates. Плюс: если правка убирала антипаттерн — назвать, какой
сторож теперь не даст ему вернуться (тест/линт-рул/комментарий), или
добавить минимальный guard.

### 4. Record + teach

- Board/audit как обычно.
- `**Lesson**` в QUESTIONS.md или в отчёт раунда: 3-6 строк сути —
  принцип, где он работает, когда не подходит, как это выглядит в
  проде/high-load контексте (не абстрактная теория — привязка к этому
  коду: «вот почему scheduler без lock дублирует работу на 2
  репликах»).
- Commit как обычно.

### 5. Report round

Один блок: **что нашёл → что спросил/решил → что сделал → урок** →
committed as <hash>. Урок пишется так, чтобы человек мог применить
его руками в другом проекте.

## Стоп-условия

- OPEN-вопрос без ответа по текущему item → ждать (можно брать
  независимые items, если не пересекаются с вопросом).
- Гейты красные → чинить, не коммитить поверх.
- Очередь пуста → сказать честно и остановиться.

## Чего mentor не делает

- Не лекцию ради лекции — Lesson привязан к конкретной правке.
- Не «как в учебнике» — показывать trade-off («валидатор на каждый
  redirect = +1 DNS, но SSRF закрыт — платим латентностью за
  безопасность»).
- Не спрашивать разрешения на каждый чих — порог «нетривиально» выше.
- Не додумывать ответы пользователя — нет ответа = нет правки по item.
