# Workflows — правила игры проекта

**Порядок чтения для любой ИИ-сессии:**

1. **`.devin/WORKFLOW.md` — ГЛАВНЫЙ ФАЙЛ.** Единственная точка входа:
   весь цикл, очередь, гейты, отчёты, стоп-условия — внутри него.
2. `AGENTS.md` (корень) — контракт: архитектура, дефекты, конвенции. **Закон.**
3. Этот файл — глобальные правила темпа/коммитов/отчётов (наследуют все
   workflow) + каталог спец-режимов.
4. `.devin/BOARD.md` — живые находки; `.devin/QUESTIONS.md` — вопросы
   человеку.

---

## Глобальные правила — наследуются ВСЕМИ workflow

### Темп (pace)

- **Один item — один раунд — один коммит.** Никогда «заодно» и «пока тут».
- **Потолок: 1,000 изменённых строк на коммит.** Больше → дроби на фазы,
  фиксируй фазу в отчёте.
- **Не начинать item с грязным деревом** (`git status` не пуст —
  разобраться или спросить).
- **Не начинать следующий item на красных гейтах.** Красное чинится до
  всего остального.
- **Нет ответа в QUESTIONS.md → item заморожен.** Брать только
  неконфликтующие items; не додумывать.
- **Очередь пуста → STOP.** Не выдумывать работу. «Ничего не нашёл» —
  валидный отчёт.

### Коммиты

- Сообщение = сообщение пользователя, если оно запустило работу; иначе
  conventional-prefix: `fix:` поведение, `refactor:` чистка, `test:`
  тесты, `docs:` доки, `chore:` инфра.
- **Никогда** AI-атрибуции, трейлеров, эмодзи.
- Board-файлы (`BOARD.md`, `done-log.md`, `QUESTIONS.md`) коммитятся
  **в том же коммите**, что и код.
- Не коммитить на красных гейтах; env-blocked гейты допустимы только с
  явной пометкой в отчёте.
- Не пушить, если не просили.

### Отчёт раунда — обязательный формат

Каждый раунд заканчивается блоком (в чат, не в файл):

```text
■ Item:    S### / defect #n / queue line — название
■ Did:     1 строка — что именно изменено
■ Files:   n файлов, +a/−b строк
■ Gates:   <lint> ✓ | <tests> n passed / env-blocked: <cmd> | <types> ±0
■ Commit:  <hash>
■ Next:    <следующий item> или STOP — причина
```

- `env-blocked` обязан нести команду разблокировки. «Не запускал» писать
  прямо.
- Никогда не писать «все тесты зелёные», если прогонялось подмножество —
  указывать scope.

### Записи на доске

- `[ ] Open` → `[x] Done` только с evidence (команда + наблюдаемый
  результат).
- Верифицирует отдельная сессия (`cleanup_verify.md`) — сам себя не
  верифицируешь.
- Находка вне scope текущего item → новая строка `Open` на доске, не
  правка.

## Два драйвера

| Файл | Режим | Когда |
|---|---|---|
| `../WORKFLOW.md` | Автономный цикл | «прогони WORKFLOW» — главная точка входа |
| `mentor.md` | Тот же цикл + обучение | «прогони mentor» — вопросы перед нетривиальным, Lesson после каждой правки |

Очередь приоритетов (общая): **PLAN → блокирующие Open-строки доски →
STOP** (внутри `WORKFLOW.md`; `self_drive.md` — только указатель на него).

### Два пространства находок — не путать

- **`S###`** — живой slop/board контур: `.devin/BOARD.md` (open) →
  `done-log.md` (closed/verify-queue). Источники: `ai_slop_audit`/
  `bug_hunt`/`deep_audit`/`full_check`; фиксит `slop_cleanup`;
  верифицирует `cleanup_verify`.
- **`#N`** — датированный аудит-борд: `.devin/audit-YYYY-MM-DD.md`
  (+evidence-лог в `.devin/archive/`). Фиксит и верифицирует
  `audit_fix_loop` — **отдельная нумерация, отдельный цикл**; не писать
  `#N` находки на BOARD и наоборот.

## Спец-режимы (узкие прогоны; заморожены — запуск по явной просьбе)

| Файл | Роль | Делает | Трогает код? |
|---|---|---|---|
| `ai_slop_audit.md` | AUDITOR | Антипаттерны/фейки по проекту → `S###` на доску | Нет |
| `bug_hunt.md` | HUNTER | Глубокое чтение: баги, дыры, мёртвый код | Только мелкие безопасные |
| `deep_audit.md` | DEEP AUDITOR | Раунды аудита: parity, wiring, bounds | Нет |
| `full_check.md` | INSPECTOR | Широтный прогон: wiring, версии, дрифт | Нет |
| `slop_cleanup.md` | CLEANER | Фиксит Open-строки минимальными диффами | Да — фиксер |
| `module_splitter.md` | SPLITTER | Режет жирные файлы по доменным швам | Да — только двигает код |
| `cleanup_verify.md` | VERIFIER | Недоверчиво перепроверяет Done-строки | Нет |
| `docs_sync.md` | LIBRARIAN | Сверяет docs с кодом, чистит протухшее | Только docs |
| `audit_fix_loop.md` | FIXER+AUDITOR | Двух-сессионный цикл по #N-борду | Да — фиксер |

## Пайплайн

```
ai_slop_audit ──┐
bug_hunt ───────┼→ BOARD (Open) → slop_cleanup ─→ done-log ─→ cleanup_verify ─→ Verified / re-Open
deep_audit ─────┤      ↑                                   │      (отдельная сессия!)
full_check ─────┘      └─ история раундов → archive/audit-log.md  │
WORKFLOW / mentor ─────── сам проходит весь цикл ──────────┘

audit_fix_loop — датированный борд #N → FIXER правит → AUDITOR-сессия
ре-верифицирует [verified]/[rejected]

module_splitter — когда файлы жиреют;  docs_sync — после раундов / перед релизом
```

**Порядок закона:** audit перед cleanup, cleanup перед verify,
верификатор — отдельная сессия от чистильщика.
