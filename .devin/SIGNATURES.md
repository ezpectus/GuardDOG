# SIGNATURES.md — каталог recurring wounds сгенерированного кода

> Классы дефектов, которые ИИ производит серийно. У каждого — grep-
> сигнатура, чтобы охота стоила дёшево. Канон: новая повторяющаяся рана
> (2+ независимых случая) → новый класс сюда с датой. Ссылается
> `AGENTS.md` §«Generated-code signatures».

## Каталог

- **Post-filter вместо WHERE.** Слой данных возвращает нефильтрованные
  строки, а tenant/user-фильтр делает вызывающий код `if`/comprehension
  → утечка между тенантами + full-table reads. Сигнатура: `list(`/
  `list_all(`/`findAll(` с последующей фильтрацией по
  `user_id`/`tenant_id`/`org_id` в caller'е. Фикс: предикат в запрос.
- **Check-then-act без lock/UNIQUE.** `max(...)+1`, `if not get(...):
  save(...)`, `+=` на read-modify-write счётчиках → потерянные апдейты,
  двойные гранты. Сигнатура: инкременты версий/счётчиков вне лока;
  dedup без DB-констрейнта. Фикс: атомарный statement / `INSERT … ON
  CONFLICT` / реальный lock — не «ещё один if».
- **Copy-paste drift.** Один список колонок/полей/параметров
  продублирован и молча разошёлся (миграция ≠ модель ≠ INSERT).
  Сигнатура: `INSERT INTO t (...)` со списком колонок ≠ CREATE/модели;
  два похожих DDL-блока в одном файле.
- **Wrong-key upsert.** Позиционные параметры схлопывают идентичность —
  display-поле попадает в PK-слот. Сигнатура: одно значение в двух
  позициях параметров INSERT/UPSERT.
- **Type-blind JSON ops.** JSON-операторы на TEXT-колонках без каста
  (PG: `->>`/`@>` без `::jsonb`) → UndefinedFunction. Сигнатура:
  JSON-операторы над `*_json` TEXT-полями; сверять с соседом, где каст
  сделан правильно.
- **Placeholder theatre.** `{{var}}` в шаблоне, который никогда не
  получает этот var → рендер пустой; потом лепятся `.replace()`.
  Сигнатура: плейсхолдеры шаблона отсутствуют в render-контексте;
  цепочки `.replace("{{x}}")` рядом с рендером.
- **Interface width as fiction.** ABC/интерфейс/endpoint есть — callers
  нет ни на одном слое. «Интерфейс существует ≠ фича потребляется».
  Сигнатура: метод/endpoint с нулём живых caller'ов — доказать grep'ом
  ДО удаления (dynamic-вызовы/`getattr`/`__all__` тоже проверить:
  «мёртвый» метод может быть живым GDPR-путём — реальный прецедент).
- **Demo data без маркера.** Статичные числа/графики, отрендеренные как
  живые метрики; `mockData`/`DEMO_`-массивы в прод-UI. Сигнатура:
  хардкод-коллекции рядом с render; endpoint, не читающий ни repo, ни
  service, ни внешний API. Фикс: label или удаление.
- **Vacuum coverage.** Тесты, по названию — integration/contract
  покрытие, по факту не трогают реальный ресурс (`issubclass` +
  in-memory roundtrip вместо живого соединения) → зелёный CI, ноль
  реальных проверок. Сигнатура: contract-test имена без
  fixture-bound connection/клиента.
- **Substring-as-identity.** `test_id in run.prompt`-style сопоставление
  → ложные совпадения. Сигнатура: `in`/`contains` по свободному тексту
  там, где нужен exact ID/tag; LIKE без экранирования.
- **N+1 fan-out.** Per-record repo/API-вызовы в цикле для агрегатов и
  batch-данных. Сигнатура: `for x in coll: repo.get(x)`; запрос внутри
  map/loop; count-per-user / get-per-id паттерны. Фикс: batch-метод.
- **Process-local state как shared.** Module-level dict/cache/сессии,
  которые «как бы общие», но живут в одном процессе → расходятся на
  2+ репликах/воркерах. Сигнатура: мутируемый module-level
  `dict`/`set`/`list`, читаемый из request-path.
- **Sync-in-async.** Блокирующие вызовы (sync HTTP, `sleep`, тяжёлый
  CPU) внутри `async def`/event-loop → реплика стоит. Сигнатура:
  sync-клиенты/`sleep` внутри `async def`; `async def` без единого
  `await` (sync, притворяющийся async).
- **Двойная правда схемы.** Два механизма создают/чинят одну структуру
  (runtime auto-DDL + миграции; два CREATE одной таблицы) → молча
  дрейфуют. Сигнатура: `CREATE TABLE`/`ADD COLUMN` вне миграций;
  повторное определение одной сущности.
- **Fake-feature shapes.** `analyze()` возвращает хардкод-score,
  `predict()` — `random`, `connect_x()` — `{"status":"connected"}` без
  вызова, «AI-analyzer» на keyword-matching. Сигнатура: функция
  «анализа/прогноза/интеграции», которая не читает входные данные.

## Как пользоваться

1. Перед фиксом — сверься с каталогом: этот дефект уже встречался?
2. Нашёл N-й экземпляр класса — не плоди находку на каждый: extends-
   запись к существующему классу.
3. Нашёл НОВЫЙ повторяющийся класс (2+ независимых случая) → добавь
   сюда с датой и grep-сигнатурой.
