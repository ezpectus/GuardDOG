# agents-workflow — переносимый комплект управления ИИ-агентом

Дистиллят `.devin/`-системы, выращенной на проекте «AI E2E QA Engineer»
(3 месяца, ~4 900 коммитов, ~287 находок аудита, ~850 `S###`-строк борда).
Вынесен сюда, чтобы тот же цикл поднимался на любом проекте за одну
adoption-сессию — **агент сам переписывает шаблон под репозиторий**.

## Что внутри

| Файл/папка | Что это |
|---|---|
| `ADOPT.md` | Инструкция ДЛЯ АГЕНТА: развернуть + переписать комплект под проект |
| `template/AGENTS.template.md` | Скелет закона проекта → `AGENTS.md` в корень репо |
| `template/.devin/` | Вся рабочая система: цикл, доска, вопросы, план, спец-режимы |

## Как применить к проекту

Скажи агенту в сессии на нужном репозитории:

```text
Adopt the workflow kit: read F:\VSC projects\agents-workflow\ADOPT.md and follow it.
```

Или вручную: скопируй `template/.devin/` в корень репо и
`template/AGENTS.template.md` → `AGENTS.md`, затем скажи «заполни по ADOPT.md».

## Почему это работает — урок, из-за которого комплект родился

Генерация кода ИИ бесплатна; верификация — нет. На исходном проекте
~50% из ~4 900 коммитов — fix/refactor/audit, `feat` = 5%. Главной
болезнью был не «плохой код», а «качественный код без потребителя»:
сотни эндпоинтов и repo-абстракций, у трети поверхности — ни одного
клиента.

Комплект кодирует механизмы, которые это лечат:

- **Маршруты задач** — каждая задача классифицируется до работы
  (read-only / bounded / durable / delegated); не каждая мысль = коммит.
- **Конечная очередь** — `PLAN.md` закрыт и не пополняется «заодно»;
  пусто = STOP, не выдумывать работу.
- **QUESTIONS-протокол** — вопрос с вариантами и рекомендацией вместо
  угадывания; нет ответа = нет правки.
- **Борд + чужая верификация** — находки `S###`; фиксит одна сессия,
  `Verified` ставит другая. Сам себя не проверяешь.
- **Гейты запускаются, не предполагаются** — `env-blocked` с командой
  разблокировки, никогда fake-green.
- **SIGNATURES.md** — каталог повторяющихся ран ИИ-кода: новые сессии
  не наступают на старые грабли.

## Границы

- Комплект рассчитан на **соло-проект с одним агентом** (WIP=1,
  файловая доска). Несколько параллельных агентов → нужны ticket-файлы
  и локи.
- Борд — память сессий, а не отчёт о качестве и не замена CI.
- Всё проектное внутри `template/` — заглушка `{{...}}`. Если после
  adoption в `.devin/` остался `{{` — агент не доделал: это баг
  adoption'а, не «пригодится потом».
