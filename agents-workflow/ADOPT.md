# ADOPT.md — инструкция для агента: развернуть комплект в этом репозитории

Тебе сказали «adopt the workflow kit». Выполняй по шагам, не пропуская.
Результат — живой `.devin/` + `AGENTS.md`, под которые реально можно
работать, а не копия шаблона с заглушками.

## Шаг 1 — Развернуть файлы

1. Скопируй `<этот kit>/template/.devin/` → корень репо как `.devin/`.
2. `<этот kit>/template/AGENTS.template.md` → корень репо как `AGENTS.md`.
   Уже есть `AGENTS.md` / `CLAUDE.md` / rules-файлы? **Не затирай — слей:**
   факты существующего важнее шаблона; шаблон даёт только недостающие
   секции и структуру.
3. `.devin/` должен попадать в git (проверь `.gitignore`) — это память
   сессий, она коммитится вместе с кодом.

## Шаг 2 — Снять слепок (verify, don't assume)

По манифестам и коду, **не по README**:

- стек/версии: `pyproject.toml`, `package.json`, `go.mod`, `Cargo.toml`,
  `requirements*.txt`, `Dockerfile`, CI-конфиги;
- entrypoint'ы, слои, где живёт состояние (memory / db / files / внешнее);
- **реальные команды гейтов — запусти каждую**: линт, format-check,
  тесты (полный прогон + scoped-вариант на один файл), typecheck, билд,
  audit зависимостей. Нерабочую команду в гейты не писать — пометить
  `env-blocked` + команда починки;
- поверхности проекта: исходники, тесты, фронтенд, CLI, docs, CI/infra;
- грубые размеры: файлов/LOC на поверхность, кол-во тестов/endpoints —
  с указанием метода подсчёта (grep-декораторы ≠ runtime-регистрация —
  это два разных числа, и путать их — классическая рана).

## Шаг 3 — Заполнить заглушки `{{...}}`

Все `{{` в `.devin/` и `AGENTS.md` обязаны исчезнуть:

- [ ] `AGENTS.md` — все секции из фактов кода (см. шаг 4)
- [ ] `WORKFLOW.md` — блок гейтов = реально зелёные команды проекта
- [ ] `PLAN.md` — конечная очередь из реальных следующих шагов (шаг 6)
- [ ] `workflows/ai_slop_audit.md` — snapshot-таблица посчитана
      (размеры + метод + дата в подписи)
- [ ] project-law таблица в `ai_slop_audit.md` — откалибрована под язык
      («no Any» — только для typed-стека; для других языков дописать
      аналоги; лишнее выкинуть)
- [ ] `.devin/BOARD.md` — шапка заполнена, нумерация начинается с S001

## Шаг 4 — AGENTS.md: что делает его законом, а не антуражем

- **«Что это»** — 2-4 строки правды, не маркетинг.
- **«Архитектура — verified truth»** — слои, state seams, кто хозяин
  схемы данных, execution-модель (sync/async/worker); каждый пункт с
  file:line. Если README рисует «Clean Architecture», а в коде суп из
  моделей — пиши суп.
- **«Target architecture»** — куда проект движется + load-failure map:
  что умрёт первым при 2 репликах / 10x нагрузке / restart. Это
  north-star — каждый дифф потом проверяется против него
  (conformance rule уже вшит в WORKFLOW).
- **«Conventions»** — ТОЛЬКО наблюдаемые паттерны: прочти 3-4 файла
  каждого домена и выпиши фактические. Выдуманная конвенция хуже её
  отсутствия — по ней начнут «чинить» живой код.
- **«Confirmed defects»** — только доказанное с file:line. Пусто →
  пиши «—». Дефекты не выдумывать.
- **«Verification commands»** — команды из шага 2, проверенные запуском.

## Шаг 5 — Подрезать под проект

- Язык не Python/TS → перепиши pattern-листы `ai_slop_audit.md` под
  идиомы языка (аналоги есть везде: `unwrap()` без контекста в Rust,
  `defer` в цикле в Go, `var`/callback-hell в JS, raw `Result.get()`…).
- Нет БД / фронта / CLI → удали соответствующие секции coverage map,
  не оставляй мёртвые чек-листы.
- Лимиты 500/50/5 строк и 1 000 строк/коммит — дефолт; меняй только с
  причиной и запиши причину в AGENTS.md.

## Шаг 6 — Первый PLAN.md

PLAN — конечный список до «базово готово», не бэклог мечты. Первые
items почти всегда одни и те же:

- [ ] **A1.** Гейты зелёные на чистом checkout/CI — запустить, не
      предположить.
- [ ] **A2.** Живой end-to-end прогон главного пользовательского флоу
      (реальный сценарий на реальной среде, не unit-тест).
- [ ] … дальше — реальные продуктовые шаги ЭТОГО проекта, по одному
      коммиту на item. Не копируй фазы из других проектов — формулируй
      по месту.

## Шаг 7 — Коммит и старт

Один коммит (`chore: adopt agents-workflow` — или по commit-конвенции
репо). Дальше вся работа — только через `.devin/WORKFLOW.md`.

## Запреты при adoption

- Не выдумывать дефекты/конвенции ради «полноты» — пустая секция честнее.
- Не копировать числа/claims из этого kit'а в проектный AGENTS.md.
- Итог ≤ ~2 000 строк: если AGENTS.md разбухает — режь. Он обязан
  читаться за 5 минут, иначе его не будут читать вообще.
