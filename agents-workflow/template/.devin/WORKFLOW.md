# WORKFLOW.md — ГЛАВНЫЙ ФАЙЛ. ВСЯ СИСТЕМА В ОДНОМ МЕСТЕ.

> **Единственная точка входа.** ИИ читает этот файл и идёт по нему целиком.
> «Прогони WORKFLOW» / «работай по workflow» — этого достаточно.
> Остальные файлы — справочники, не точки входа:
> `AGENTS.md` (корень) — что ПРАВДА в проекте (закон) · `QUESTIONS.md` —
> вопросы человеку · `PLAN.md` — конечная очередь до «базово готово» ·
> `BOARD.md` — доска находок · `workflows/README.md` — спец-режимы
> (по умолчанию заморожены — см. Шаг 2).

## ШАГ 0 — ОРИЕНТАЦИЯ (каждый запуск)

1. `git status` + `git log --oneline -3` — дерево должно быть чистым.
   Грязное и непонятно чьё → спросить, не трогать.
2. `QUESTIONS.md` — есть OPEN без ответа? → эти items заморожены.
3. `AGENTS.md` §«Confirmed defects» + §«Target architecture» — приоритет
   и north-star техники.
4. `.devin/PLAN.md` — первая `[ ]`-строка = текущий item.
5. `.devin/BOARD.md` — строки `[ ] Open` (только блокирующие план).

## ШАГ 1 — МАРШРУТИЗАЦИЯ (классифицируй задачу ДО работы)

Каждая задача получает один из 4 маршрутов:

| Маршрут | Что это | Правила |
|---|---|---|
| **READ-ONLY** | вопрос, объяснение, аудит | Ничего не менять. Ответ с file:line evidence. |
| **BOUNDED** | правка ≤1 файла, очевидная (lint, typo, stale-claim, уже согласованное удаление) | Делать сразу. Коммит + отчёт. |
| **DURABLE** | поведение/контракт/схема/удаление живого кода, ≥2 файлов | Сначала Q-entry в `QUESTIONS.md`, ждать ответа. |
| **DELEGATED** | «разберись и скажи что делать» без правок | Находки на доску/в отчёт. Код не трогать. |

Сомневаешься между BOUNDED и DURABLE → DURABLE. Цена лишнего вопроса —
минута; цена угаданной неправильно правки — откат и потеря доверия.

## ШАГ 2 — ВЫБОР item ИЛИ вопрос

**Очередь приоритетов (сверху вниз):**

1. `.devin/PLAN.md` — первая `[ ]`-строка. Это единственная активная
   очередь; список конечный и доводит до «базово готово».
2. `Open`-строки доски — только если **блокируют** текущий item плана.
3. Пусто → проект базово готов → честный STOP. **Никогда не выдумывать
   работу**: не запускать аудиты «для профилактики», не чистить «пока тут».

**PARKED-режим:** находки вне текущего item → секция PARKED в конце
PLAN (короткой строкой). PARKED — склад, не очередь; не выполняется,
пока план не пуст.

**Спец-режимы заморожены по умолчанию.** `ai_slop_audit`/`deep_audit`/
`bug_hunt`/`full_check` запускаются только по явной просьбе человека.
Причина — выученная на своих шрамах: бесконтрольные аудит-прогоны —
фабрика бесконечной чистки, находок становится больше, чем фиксов, и
проект превращается в самообслуживание. Уже существующий датированный
борд фиксится через `workflows/audit_fix_loop.md`.

### Протокол вопросов — `QUESTIONS.md` (встроен в этот workflow)

**Когда вопрос ОБЯЗАТЕЛЕН:** меняется контракт/поведение; ≥2 разумных
варианта; удаление кода, который может быть живым; новая абстракция/
endpoint; странная функция, чьё назначение непонятно; любой маршрут
DURABLE.

**Формат entry в `QUESTIONS.md`:**

```markdown
## Q-NNN · `path/file.ext:123` · OPEN
**Найдено:** что именно, 1-2 строки
**Почему пахнет:** имя антипаттерна / нарушенный принцип
**Варианты:** A) … B) … C) …
**Моя рекомендация:** … (1 строка)
**Ответ:**
**Lesson (после решения):** 3-6 строк сути принципа
```

**Правила вопросов:**
- Вопрос без вариантов и рекомендации ЗАПРЕЩЁН («что делать?» = лень).
- Написал вопрос → скажи человеку «прочти QUESTIONS.md Q-NNN» → **жди**.
  Нет `**Ответ:**` = нет правки. Никогда не додумывать.
- Нумерация сквозная. OPEN → ANSWERED → DONE(+Lesson) → Archive.
- НЕ спрашивать про тривиальные BOUNDED-правки по согласованным правилам.

## ШАГ 3 — СДЕЛАТЬ (минимальный дифф)

- Одна правка = один коммит. Потолок **1,000 строк**.
- Конвенции — `AGENTS.md`. **Architecture-check** (его §Target
  architecture): запрещено в диффе — новый process-local state, долгая
  фоновая работа в request-path, абстракция без потребителя, endpoint
  без клиента, второй движок существующего контура.
- Удаления — только после grep по репо + docs + tests + workflows.

### Always / Ask / Never — три корзины решений

| ALWAYS (делай молча) | ASK FIRST (Q-entry) | NEVER |
|---|---|---|
| lint/typo/стили по конфигу | контракт API, схема данных | fake-green, пропуск гейтов |
| правка stale docstring | удаление живого кода | новый endpoint без клиента |
| закрытие отмеченного мёртвого | новая зависимость | коммит секретов/.env/дампов |
| синк docs с кодом в том же коммите | поведение по деньгам/тенантам | перепись рабочей инфры без решения |
| PARKED-запись для вне-scope находки | архитектурный выбор ≥2 вариантов | новые фичи/аудиты вне PLAN |

## ШАГ 4 — ПРОВЕРИТЬ (запустить, не предположить)

```bash
{{GATES — заполняется при adoption реальными командами проекта.
Структура, которую нужно сохранить:
```

`env-blocked` → писать команду разблокировки. Никогда fake-green.
Красный гейт → чинить до всего остального, не коммитить поверх.

## ШАГ 5 — ЗАПИСАТЬ + ЗАКОММИТИТЬ + ОТЧИТАТЬСЯ

- Доска: `[ ] Open` → `[x] Done` **с evidence** (команда + результат).
- Коммит: сообщение = сообщение пользователя, иначе `fix:`/`refactor:`/
  `test:`/`docs:`/`chore:`. Board/docs-файлы **в том же коммите**.
  Никогда AI-атрибуции. Не пушить без просьбы.
- **Отчёт раунда — обязательный шаблон:**

```text
■ Item:    S### / defect #n / queue-line — название
■ Route:   read-only | bounded | durable | delegated
■ Did:     1 строка — что изменено
■ Files:   n файлов, +a/−b строк
■ Gates:   <lint> ✓ | <tests> n passed / env-blocked: <cmd> | <types> ±0
■ Commit:  <hash>
■ Next:    <item> или STOP — причина
■ Lesson:  (только режим mentor) 3-6 строк сути принципа
```

## СТОП-УСЛОВИЯ

Красные гейты · неотвеченный OPEN-вопрос блокирует item · выбор
архитектуры → Q-entry · грязное дерево непонятного происхождения →
спросить · страшное вне scope → PARKED-запись, не правка влёт ·
**PLAN пуст → проект базово готов → STOP без новой очереди**.

## ЧЕМ ЭТО ОТЛИЧАЕТСЯ ОТ «ПРОСТО AGENTS.md»

Маршруты задач (Шаг 1) вместо «делай что попросили» · конечная очередь
и честный STOP вместо вечной полировки · вопрос-протокол с гейтом
«нет ответа = нет правки» · доска находок с раздельной верификацией
(фиксит одна сессия, подтверждает другая) · каталог recurring wounds
(`SIGNATURES.md`) — память между сессиями.
